# 地形与通行效率改进验收

本次目标保留用户提出的七项要求；以下是实现和验收依据。

1. 识别与配准完成后自动贡献等高线并重建。未标高的线以独立的同高约束参与，不能假定每段都是零海拔、也不能给互不相连的线编造高差。没有高程参考的部分等待轨迹；可靠的人工标高可选。重复识别、重配准和恢复任务不能重复计权或覆盖人工修正。
2. 用真实大沙河原图验证大片橄榄绿色禁区；保持亮绿植被和已有道路、浅灰通道的区别。升级通行识别版本。
3. 自定义点序以纵向“第几站 / 目标编号”呈现；明确起终点和上移、下移、移除，验证桌面和窄屏操作。
4. 大地图支持纯等高线透明叠层，覆盖共享、课程冻结和实时地形；共享页三维可开关等高线，与二维使用同样的间隔和数据空白。
5. 可选某条贡献，只展示它的采样、覆盖和统计；分别说明原始高程、共同重建校正值及学习贡献，退出后恢复全区。选择不修改参与重建开关。
6. 展示学习样本量、有效移动/停留/剔除数据、配速变化、坡度响应和局部通行效率；地图呈现学习路段，路线呈现覆盖和耗时构成。数据不足明确展示基础估计。
7. 跑走共同学习徒步相对通行效率；每次记录及持续配速变化单独估计，骑行仍独立。保留历史标签兼容、冻结课程和旧模型读取，不要求给混合跑走轨迹逐段分类。

验证以当前代码、自动化流程和真实原图/KML 的隔离重建为准；历史报告不作为本次通过依据。

七项的完成证据已保存到 [terrain-efficiency.json](../evidence/runtime/terrain-efficiency.json)。472 项后端、36 项前端、完整 64 个浏览器流程通过；最后的显示筛选及离线缓存以 7 个相关流程和真实数据生产页面补验。实际原图的识别、自动入模、颜色分类、合法路段及每条贡献的查询均重新执行。没有把仍需参考的等高线段填为零，也没有为通过连通性检查而开放禁区。

发布沿用 main 的 GitHub Actions，部署验收以公网 /api/health 的 revision 为准。旧版关于跑步单独学习、逐条等高线核对的说明，以本轮实现和新报告为准；历史验证记录保留原文。

用户追加要求已纳入：完整保留自动到访调整，并在验证后推送部署。圈心与到访点分开，私有绿地仍阻挡路线；32 个目标都可自动规划，既有 15 处已保存到访位置通过新通行图复核且保持原值。实际部署通过 main 的 GitHub Actions 发布和公网 revision 检查验收。
