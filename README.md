# DirMap · 深大定向

定向越野课的教师工作台和手机网页，使用目录中的深圳大学地图、两张图例及后来导入的地图。现已能自动叠合地图、识别检查点、跟随手机朝向，并根据人数、队伍和课程规则规划路线。场地除深大粤海校区外还内置大沙河公园，也可按地图视野添加其他地点。注册账户后每人有独立的工作台；学生用课程链接或 6 位组队码即可，无需注册。**当前仍是待现场验收的开发版，尚未完成完整目标。**

## 启动

本机运行：

```bash
./tools/run.sh
```

打开 **http://localhost:8765**。新环境或 `/tmp` 被清理后先运行：

```bash
./tools/setup.sh
./tools/run.sh
```

已在 Ubuntu 26.04、Python 3.14.4、Node 24.16.0 验证。服务进程会让大数组直接向系统申请和归还内存，并在每个任务后释放空闲页；最大的拼版图（3613×4096 工作图）一次通行更新峰值约 0.94 GiB，结束后约 0.55 GiB，可用 `python3 -B tools/benchmark_memory.py --baseline <提交>` 对照。依赖锁为 `requirements.lock` 与 `package-lock.json`。Python、Node、OCR 和通行图缓存均放在 `/tmp`；无需下载大模型、浏览器或启动 Codespace。已有 C++ 编译器时会编译一个很小的最短路加速模块，没有编译器则使用 SciPy。

识别、通行更新、同名点校准和规划任务保存在 `data/jobs/queue.sqlite3`。页面刷新后会接续正在查看的任务，也可从地图列表下的“处理记录与恢复”重新打开结果。服务重启会先检查原任务是否已经提交，再继续未完成的计算；期间有教师修改或程序更新时会保留新数据并要求重新提交。新的障碍图与叠层按整套文件发布，重启不会混用不同版本。

进度条下的“取消任务”可停止误点或过慢的处理：排队中的任务立即取消；运行中的任务在当前步骤结束后停止，不发布半成品。取消请求到达前已经提交的结果照常保留并显示为完成。再次提交完全相同的任务会撤回尚未生效的取消。

安装脚本尝试把 Debian/Ubuntu 的 Tesseract 包解压到临时目录，不执行系统安装。其他系统可自行安装 Tesseract；没有 OCR 时仍能识别圈，编号保留待核验。可用 `DIRMAP_TESSERACT` 和 `TESSDATA_PREFIX` 指定已有 OCR。

## 手机 HTTPS

手机与电脑接入同一网络后运行：

```bash
./tools/run-https.sh --port 8766 --serve-ca
```

脚本打印手机访问地址、公有 CA 证书下载地址及本机教师口令文件位置。证书和私钥默认保存在 `~/.local/share/dirmap/tls`，不会修改电脑或手机的系统信任设置。

1. 手机下载打印地址中的 `ca.crt`，安装并信任这个本地 CA。iOS 还需在“设置 → 通用 → 关于本机 → 证书信任设置”开启完整信任；Android 可在设置中搜索“安装 CA 证书”。
2. 重新打开打印的 HTTPS 地址，确认浏览器已信任连接，再开启定位和罗盘权限。
3. 教师注册账户，在自己的工作台中操作；或不登录，在“使用说明”中填写本机口令文件里的内容，使用原工作台。核验并发布课程后，给学生课程链接。

定位停止更新后会自动重新取点；超过 10 秒仍未获得新位置时，地图保留灰色的上次位置，并暂停显示实时目标距离。鸿蒙微信已加入定位时钟兼容处理。若仍异常，可在“使用说明 → 定位诊断与重试”中重新定位、查看版本并复制诊断；诊断不包含经纬度。浏览器回归不能代替手机现场验证。

证书文件 `ca.crt` 可分发；私钥和教师口令留在教师电脑上。已有正式 HTTPS 域名时也可以使用反向代理，并设置 `DIRMAP_ADMIN_TOKEN`。本地 HTTPS 已做证书链和页面访问检查，**这不等于 iOS/Android 真机行走测试**。

## 功能与边界

- **账户与独立工作台**：右上角“登录 / 注册”。每个账户有自己的工作台（`data/workspaces/<编号>`），其中的地图、识别与规划记录、同名点、核查点和已发布课程只属于这个账户；在自己的工作台中导入地图、识别、生成路线和发布课程都不需要教师口令。同一浏览器中的课程草稿、场地选择和待恢复任务也按账号保存，切换账号时其他工作台标签页同步重新载入，旧页面的操作会被拦下。新工作台带有从程序自带原图独立生成的三张公共示例，需要重新核验后才能发布；公共样例不包含其他账户的校准、改点或通行编辑。主体文件以硬链接共享，账号分别保存自己的元数据和修改。服务器原来的单教师工作台（数据目录根下）保持不变：未被认领前，未登录的访客照旧使用它，修改仍需原教师口令；原教师注册时勾选“我是服务器原工作台的教师”并填写原口令即可认领，之后未登录的访客只看到登录页，课程链接和组队码不受影响。已有地图改动或处理/规划记录的独立工作台不能被认领操作替换。密码用 scrypt 保存，登录保持 30 天（HttpOnly、SameSite=Lax，HTTPS 下加 Secure），改密码会退出其他设备。同一地址 15 分钟内登录失败 100 次、同一用户名失败 10 次后暂停，同一地址每小时最多注册 60 个账户。各账户共用一个任务队列，每个账户同时最多 4 个排队或进行中的任务；每个工作台最多导入 30 张地图，服务器剩余空间不足 2 GiB 时暂停导入。
- **组队定位**：课程页的“组队与位置共享”或 `/?group=` 页面中，填写显示名称后创建小组，得到 6 位临时组队码（可复制带码的邀请链接 `/?group=123456`）；同伴输入组队码加入，无需账户。每人自行打开“共享我的位置”后，组员在地图上看到彼此的位置、精度与是否过时，列表显示相对自己的方向和距离；还可发消息和快捷短语、在地图上标记集合点、发出求助（组员手机振动提示，求助时自动开启共享）。组长可锁定小组、移出成员或解散；组长退出后由最早加入的成员接任。页面打开时每 3 秒同步一次，失败时退避；网页切到后台或锁屏后，浏览器会暂停定位和同步，组员看到的是最后一次位置及其时间。位置只在共享期间保存，关闭共享、退出或被移出时立即删除，最后一次定位超过 15 分钟不再显示。小组闲置 6 小时或创建 24 小时后连同位置和消息一起删除，最多 60 人。从课程页创建的小组属于该课程：发布课程的教师可在“已发布课程”中打开“小组位置 ↗”（`#groups`，只读）查看本课所有小组的成员、位置、集合点和求助；持有课程链接的学生不能查看（原工作台的课程需原教师口令）。同一地址 10 分钟内输错组队码 60 次后暂停加入。
- **场地**：每张地图属于一个场地，每个场地有自己的 OpenStreetMap 参照和本地米制坐标原点；自动配准只与同一场地的参照和图幅匹配，叠合图幅也只叠同一场地。内置“深圳大学粤海校区”和“大沙河公园”（约 1.6 × 1.7 km 范围的 682 个参照地物，随程序发布；`python3 -B tools/fetch_reference.py --site dashahe-park` 可重新下载）。公园图幅常没有完整的湖面，水体匹配不足时改由形状独特的建筑起配。其他地点可用“＋ 场地”：把地图移动、缩放到场地范围（边长 150 m–3 km），服务器从公共 Overpass 镜像下载其中的建筑、水体、道路和绿地，每个工作台最多 8 个；下载失败时保留已有参照，没有参照时可用同名点手动配准。学生页使用课程所在场地的参照和该地的磁偏角，离线保存课程时一并保存。大沙河公园尚无真实定向图，[合成图检查](evidence/runtime/dashahe-synthetic.json)用其 OSM 参照按 ISSprOM 配色渲染、已知旋转与比例的短距离图跑完整流程：建筑起配成功（自动留出 P95 3.43 m），8 个检查点全部识别和校准（与真值的中位/最大偏差 0.77/1.45 m），起终点识别，2 队分担路线证明最优。这验证场地坐标系、参照与处理流程，不代表真实印刷公园图的识别精度，可用 `python3 -B tools/verify_dashahe.py` 复现。
- **小组打点照片**：学生从课程页创建或加入小组后，点目标旁的“照片”或“组队与位置共享 → 小组打点照片”。每个课程检查点共用一张照片，组员均可拍照、上传、查看、替换或删除；相册包含本课各队涉及的检查点，导出包含小组已上传的全部照片。支持 **PDF（每张一页）、长图、多图 ZIP**，每张照片的像素中都会加上 `CP 检查点编号` 水印（支持中文编号），有系统分享功能的手机也可把文件分享给其他应用。长图生成后可点“查看水印长图 / 保存图片”，滚动核对全部照片与编号，并使用图片的长按保存菜单；关闭按钮始终保留在顶部。浏览器不支持或拒绝分享时，下载仍可使用，取消分享不会清理照片。先打开导出文件、确认完整并保存或提交其他平台，再点“已保存，结束并清空已导出照片”；这只清除本次导出的版本，组员随后上传或替换的照片会保留。小组解散、最后一人退出、闲置 6 小时或创建 24 小时后，服务器自动清理照片。上传前会压缩到最长边 1600 像素并移除 EXIF/GPS，输入最大 20 MiB、每组最多 120 MiB；长图较多时会缩小，需要清晰照片可选 PDF 或 ZIP。未上传成功的照片暂存在该设备，刷新后可重试，联网后自动补传；若同一点已被组员更新，会提示查看后再确认替换。照片不能从教师只读总览或其他小组读取。课程后来失效仍可整理和导出已有小组照片。
- **原图缩放与选点确认**：配准同名点、现场核查点、新增目标、到访位置和换层入口均先显示待确认标记，可反复点选调整，按“确认选点”才采用。原图支持拖动、滚轮和双指缩放，“全图”恢复视野；绘制通行区域时可切“移动地图”，双指缩放不会留下笔刷痕迹。标准地图设置配准点、起终点或小组集合点时也显示预览、坐标和确认/取消按钮，配准可返回重选原图位置；已经添加的同名点保留编号标记，便于核对。
- **配准与点位**：水体和建筑匹配、RANSAC、观测到的建筑角点、局部网格修正；低清图通过共同地物继承高清图的地理配准。原图和检查点使用同一坐标变换。基准图重新校准后，依赖它的旧叠层和课程会失效；只改编号不会使几何配准失效。
- **现场 GPS 核查**：“地图配准”页可用手机当前定位添加独立核查点：站在原图上能认出的位置，记录定位及其精度，再在原图上点出所站位置。核查点不参与拟合，单独保存，不改变地图版本，也不会让路线或已发布课程失效。页面按当前配准实时给出可用点的中位、P95 与最大误差，并在至少 5 个可用点后对照验收门槛（中位 ≤3、P95 ≤8、最大 ≤12 m）；精度差于 10 m 或在配准范围外的点保留但不计入，误差中包含手机定位误差。在“地图配准”页时，地图上会画出每个核查点的手机定位与按配准推算位置之间的连线（绿色 ≤3 m、橙色 ≤8 m、红色更大、灰色不计入），便于找出需要补同名点的区域。
- **识别与核验**：检查圈、起终点、数字编号、建筑、水体、植被和禁入填色；分离紫色课程连线，恢复被遮挡的屋顶、水体和围墙，避免将连线识别成道路。原图中可改编号、实际到访位置和通行区域。圈心画在雕塑、喷泉或建筑边缘时，可建议附近合法到访位置。圈心仍保留，建议须由教师确认。
- **独立起终点**：支持普通三角形起点、双圆终点及组合起终点，独立起点按三角形重心定位；起终点不同时默认采用图上的终点。旧图可点“更新识别与通行”，保留已有配准和人工修正，核验后重新发布。识别版本过期时课程页会提前提示更新，原小组照片仍可整理和导出。
- **照片拼版与大图**：按课程油墨和重复圈径识别检查点，减少照片装饰与数字空洞的误检。支持最大 20 MiB、两亿像素以内的 JPEG/PNG；大图按最长边 4096 像素生成工作图，正确处理 EXIF 朝向，保留原文件与坐标换算。编辑和路网检查使用同一工作图，不能据此声称检查了大图的每个原始像素。
- **路线**：每队全点、全班分担、固定顺序、混合覆盖四种模式；支持人数、队数、速度、不同起终点和错峰。图 3 按已确认规则默认让每队到访 31、32、33，其余 13 点由全班分担；必到点的先后顺序可另行指定。自适应通行图保留原像素的窄门和细墙；每条路径均沿合法图边展开。小问题用完整动态规划，大问题用 CP-SAT 和可行路线作为初始解；可选 5 秒或 30 秒计算预算。
- **多层通行**：原图编辑器的“桥隧与层级”可新建桥面、地下通道等层级，在该层描画可行走范围，再在两层实际相接处标记换层入口（可填写额外长度和耗时系数）。平面上重叠的道路不会自动互通；只有教师核验过的层级和入口加入路网。目标和起终点可指定到访层级，路线、学生页和离线课程标出换层位置；偏航重算时可选择当前所在层级。校园参照中的桥隧位置只能载入为待核验草稿。
- **灰白斜纹下层**：按已确认的图例含义，把重复的灰白斜纹识别为架空或下层可通行区域，只去除斜纹本身；实心屋顶、黑色边界、柱体和禁区仍阻挡。下层范围另存为语义，教师在其上方绘制桥面层时下方仍可通行。斜纹规则只在本图族上开发验证。
- **减少网格绕行**：在同一均质地形内补充经过逐像素检查的斜向连接，减少开阔地的折线。连接不穿过障碍或不同代价的地形；存在局部配准变形时只在同一仿射区域内连接。原有节点、通道和边保留，最短路径仍由完整图计算，路线和距离使用同一批连接。
- **最优性**：仅完成证明时显示“模型内已证明最优”。大规模限时结果可能只是“当前最佳可行”；CP-SAT 的证明范围明确为毫米/毫秒量化的静态模型。人数影响打点耗时，目前没有动态拥堵、容量和时窗排程。
- **按收益自动分队**：在“课程设置 → 按分队收益自动选择队数”中设置每队最少人数、最多队数和收益保留比例。系统比较允许的全部队数，沿用当前的覆盖规则、速度、出发间隔与优化目标，自动采用达到指定收益比例的最少队数；没有收益时建议 1 队。默认保留本次计算最佳改善收益的 90%，每队至少 2 人（可改为 1 人）。页面列出预计最晚完成时间、总路线长度和各方案的证明状态。该功能支持全点、分担、固定顺序和混合模式；自定义点序的队数保持由教师指定。
- **采用比较方案**：比较表中的队数按钮可直接采用该档已计算的分队和点序，不重新优化。“自动建议”和“当前采用”分别标注；刷新后可从处理记录恢复，核验发布时也保留所选队数与路线。地图、点位、耗时设置或规划程序变化后需要重新比较。旧记录未保存备选点序时会提示重新比较。
- **继续优化当前路线**：结果中的“继续优化，最多 30 秒”以当前路线为起点，保持队数、人数、速度和课程规则，继续调整分配与点序。页面显示优化前后指标；没有更好的结果时保留原路线。自动分队方案只更新本次选择的队数，其他档位仍可采用，收益与建议会同步重算。计算中刷新可接续原任务，核验发布时保留最后选定的路线。固定/自定义点序和已证明模型最优的方案不需要继续搜索；旧记录缺少复算数据时需重新生成。
- **手机导航**：iOS 罗盘、绝对方向、屏幕旋转补偿、过北滤波、稳定 GPS 航向回退、北向上和拖动暂停；可用已知方位校准罗盘。持续偏航时，按本队尚未完成的点序重算合法路线；定位不可靠或落在障碍上时要求重新定位。
- **路线与自身方向**：规划和学生导航路线沿行走顺序显示小箭头；定位圆点旁显示方向短线和箭头，蓝色“手机指向”为罗盘方向，绿色虚线“行进方向”为可靠的 GPS 移动航向。地图旋转时箭头随实际地理方向旋转，定位或方向过期时收起自身方向标识。可在“图层”分别关闭“路线箭头”和“我的方向”，选择在本机保留。
- **课堂与离线**：教师核验后发布不可变课程；学生选队、本机打点和撤销。正式构建可保存最近三份课程的原图、路线和目标，断网后可重载页面。离线时标注无法获取教师更新；已知失效的课程不会因断网重新启用。标准地图瓦片不批量下载或缓存。
- **纸质路线**：学生页“打印本队路线”、教师发布结果和“已发布课程”中的“打印各队路线”生成每队一页的 A4 路线单。服务器在课程发布时冻结的叠层图上画出建议路线、本队到访顺序、起点三角形和终点双圈；浏览器排版队伍、人数、距离、预计用时和目标表（含计划到达时间及留空的打点时间栏）。图片约 0.5 MB，只含线条和数字，不依赖服务器中文字体。
- **课程二维码**：发布结果和“已发布课程”中的“二维码”弹出学生课程链接的二维码，可投屏让学生用微信或相机扫码进入。二维码由服务器的 OpenCV 生成，链接使用教师当前访问的站点地址。
- **开课计时与错峰出发**：教师在“已发布课程”中点“开始计时”后，各队手机显示开课时长和本队出发倒计时（出发前一分钟高亮），时间按服务器时钟校正，联网获知后离线也能继续计时。成绩表增加“距开课”一列。可随时重置计时。
- **全班进度与集合**：学生每次打点、撤销或从集合点出发后，联网时会上报本队进度（已完成的目标、本机记录的打点时间和已离开的集合点），不包含位置。在全班集合点等待时，页面显示已到达的队伍和未到队伍；“全班进度”汇总各队完成数和最近打点，教师可在发布结果中打开“查看全班进度”（只读，不显示打点按钮）。断网时打点照常保存在本机，联网后补传；同一队多部手机按最远进度合并，旧的或重复的上报不会覆盖新状态。是否统一出发仍由现场确认。完成本队全部目标后点“已到达终点”记录到终时间（可撤销），全班进度显示各队到终情况。工作台地图列表下的“已发布课程”列出本图最近发布的学生链接、是否已失效和各队打点概况；刷新或换一台电脑后也能找回课程，设置了教师口令时需要口令。“全班进度”可导出成绩表（CSV，每队每个目标一行、末行为终点，含手机记录的打点和到终时间），本队目标列表也显示各点的打点时间。

源数据、配准和路网修改会使相关旧路线失效。通行图缓存最多六份、256 MiB，默认位于 `/tmp/dirmap-cache`，可用 `DIRMAP_CACHE_DIR` 改位置。缓存清空后会从原数据重建。

另在空白临时项目中完整重跑三张原图，不复制已有配准、目标或通行图缓存：32 个编号及 3 个起终点均与清单一致，三图预处理约 65/24/39 秒，峰值 RSS 约 1.16 GiB。重跑的自动 P95 为 7.45/1.50/8.49 m，图 2 仍是继承基准图误差的接缝核查。这验证了自动处理入口，不能替代独立定位和现场通行基准，见 [从零处理记录](evidence/runtime/fresh-processing.json)。

30 个模拟检查点放在图 3 的实际通行图上、10 队分担的性能检查已生成 [性能记录](evidence/runtime/planning-performance.json)。它计入图加载、点间矩阵、优化和路径展开，区分已准备图数据的冷加载与内存缓存；不是新增 30 个真实检查点的识别验收。

自动分队复用一次点间路程计算；全点及固定顺序复用同一条路线，小型分担问题复用子集最短路表。混合模式的路线改进按全班完成时间判断，计入集合等待。图 3 的全部 16 点、20 人、1–10 队比较，在一次本机检查中分别用时约 3.51 秒（全点）和 4.97 秒（混合）；混合模式当前建议 4 队，比本次 1 队方案的最晚完成时间少约 32%。限时方案的比较不代表全局最优队数。详见 [分队收益与算法性能记录](evidence/runtime/team-planning-performance.json)，可用 `python3 -B tools/benchmark_team_planning.py` 复现；教学数据在临时副本中检查。

限时求解还会尝试同队移点、跨队交换和不同集合顺序，并保留已有更优结果；自动比较后会集中一部分预算细化最终推荐路线。每队恰好一个点采用快速精确匹配，单队和固定集合顺序也有直接求解分支。同一图 3 输入、同样 5 秒求解预算的配对检查中，最晚完成估计比旧算法减少约 71 秒；详细范围及重复结果见 [路线质量记录](evidence/runtime/route-quality.json)，可用 `python3 -B tools/benchmark_route_quality.py` 复现。

移点和交换的候选评分只重算变化的路段与集合阶段。同一批候选的评分约快 4.9 倍（分担）/6.5 倍（集合），不代表整个规划 API 的加速。图 3 通行图上采样 30 点、10 队，在相同 5 秒求解预算下，最晚完成估计进一步缩短约 16 秒；原有 16 点课程的推荐保持 4 队。范围与重复结果见 [邻域搜索对照](evidence/runtime/route-neighborhoods.json)，可用 `python3 -B tools/benchmark_route_quality.py --baseline 94d104b --output evidence/runtime/route-neighborhoods.json` 复现。

精确细化会保留初始方案和各完成阶段中未取整指标最好的路线，避免第一目标相同却增加总耗时，也避免取整后选中的路线反而更长。最优证明必须对应最终返回路线；保留的路线未达到该量化模型最优值时显示“当前最佳可行”。用例与实图复测见 [已有方案保留检查](evidence/runtime/route-incumbents.json)，可用 `python3 -B tools/benchmark_route_quality.py --baseline 29ecfb2 --output evidence/runtime/route-incumbents.json` 复现。

底层路径对照见 [开阔地与实图路径检查](evidence/runtime/path-quality.json)。无障碍场地的 506 个方向/距离组合中，网格绕行误差中位数从 5.92% 降至 1.21%；图 3 的 306 个有向点对均未变长，中位路径代价减少约 2.81%。保持相同 4 队与访问顺序，总路线约缩短 325 m，预计最晚完成时间约缩短 58 秒。点间矩阵在本次检查中约 1.13→1.26 秒，节点数不变。可用 `python3 -B tools/benchmark_path_quality.py` 复现；结果限定在准备好的通行模型内，不代替现场验收。

当前路由版本为 `native-quadtree-v8-explicit-surfaces`，通行识别版本为 `print-scale-boundaries-v6-lower-level-hatching`。已有地图会显示“更新识别与通行”，更新后保留原图、点位、配准和通行修正；旧路线及旧计算记录需重新生成。灰白斜纹开/关的通行与路程对照见 [下层斜纹检查](evidence/runtime/lower-level-hatching.json)：没有新增封闭像素或变长的点对，拼版图部分点对缩短最多约 10 m。

按用户要求，不考虑检查点接待人数或对应的排队限制。人数继续用于均衡分队、速度设置及已有的打点耗时估计。

备选方案只保存点序、证明及复核所需的模型数据，不重复保存地图或整张通行图。图 3 的 16 点实图检查中，保存 1–10 队比较约占 29 KB；采用另一档约 2.1 秒，核验后点序、路线坐标和时间保持一致。检查在临时副本完成，见 [方案采用记录](evidence/runtime/team-choice.json)，可用 `python3 -B tools/verify_team_choice.py` 复现。

普通规划也会保存点间矩阵和原方案，以便继续计算和核验恢复；没有复制图片或整张通行图。固定队数、比较后选定队数的完整流程见 [继续优化检查](evidence/runtime/plan-refinement.json)，可用 `python3 -B tools/verify_plan_refinement.py` 在临时副本复现。新的 `POST /api/plans/refine` 和 `POST /api/plans/confirm` 使用原方案标识，校验地图、输入、程序和记录指纹；确认接口只复核恢复，不再次优化。

## 验证与继续工作

```bash
source tools/runtime-env.sh
python3 -B tools/prepare_maps.py             # 保留现有校核，准备通行图缓存
python3 -B tools/verify_inventory.py          # 编号及起终点清单
python3 -B tools/verify_detection.py          # 新照片拼版图及缩放/白边/JPEG 变体，完全从图像重识别
python3 -B tools/verify_runtime.py            # 全图优先检查，再测可达子集
python3 -B tools/verify_course_regressions.py # 课程连线遮挡与混合覆盖的实图回归
python3 -B tools/verify_lower_level.py        # 灰白斜纹开/关的通行和点间路程对照
python3 -B tools/verify_fresh.py              # 临时空白项目中完整重跑三张原图
python3 -B -m pytest -q tests
npm test
npm run build
DIRMAP_BROWSER_PATH=/usr/bin/google-chrome npm run test:browser
```

浏览器检查使用已有 Chromium/Chrome，在临时副本和独立的 5174/8768 端口中发布测试课程，不复制正在使用的工作台任务队列，也不访问外部底图服务。覆盖手机尺寸、罗盘事件、离线重载、打点、偏航重规划、混合覆盖、课程失效，以及丢失提交响应/进度连接后的页面恢复。后端另用真实子进程中断和两个独立服务进程验证恢复及编辑冲突。它们仍不能代替真实手机传感器和校园试走。

网页再次“自动识别与配准”会保留同一原文件的教师补点、确认/排除、手动编号、通行修正和人工配准，按位置合并新的候选；已删除的候选不会重新加入。教师补的 43 号点不会被覆盖或重复添加。

识别规则升级后，旧地图会显示“更新识别与通行”，完成更新后才能规划。该操作重新识别自动候选点和通行区域，原样保留现有地理校准、教师补点、确认/排除、手动字段与通行修正；基准图配准已变化的图幅需要先重新配准。

`prepare_maps.py --refresh-recognition` 提供相同的识别升级操作。`--refresh-ocr` 只重识别自动编号，保留教师编号和几何校核；变化会生成新版本。`--refresh-terrain` 保留全部点位与配准，只更新通行识别。`--force` 会重做整图并替换既有校核，可配合 `--asset szu-2` 限定图幅。`tools/acceptance.py` 对完整课程逐图审计；图 2 的禁区冲突会使它如实返回非零。

`state.json` 中的 `artifacts` 指向不可变的派生文件；外部工具应通过 `store.artifact_path(state, name)` 读取当前障碍图，而非固定读取旧的同名文件。历史任务和结果留在 `data/jobs`，课堂包留在 `data/releases`。服务空闲时每 6 小时整理一次：每张图始终保留最近 20 份任务结果、规划和分队比较记录，超过 30 天的更早记录只保留任务摘要（处理记录显示“结果已清理”），仍被保留规划引用的比较记录不删除；已发布课程自带路线和叠层，不受影响，课堂包也不自动删除。备份或迁移项目时需要保留整个 `data` 目录。

Git 仓库包含源码、测试、原三张地图、两份图例及校园参照。教师导入的地图、校核状态、派生图、任务队列、已发布课堂和本地备份不进入 Git，仍保存在本机 `data` 目录。新克隆可运行 `./tools/setup.sh` 重建原三图；复现新增上传图的检查或迁移现有课堂时，还需单独复制相应的 `data` 数据和原文件。推送源码不能代替教学数据备份。

上传地图按当前数据目录下的 `projects/<地图 ID>/source.img` 读取；新记录使用相对路径，旧记录里的绝对路径无需手工修改。把整个 `data` 目录复制到另一台电脑后，可设置 `DIRMAP_DATA_DIR` 指向它；即使旧位置还存在，也只读取选定工作台中的原文件。

新增照片拼版图的识别脚本和浏览器回归默认读取 `evidence/new-map-fixture.json` 指定的项目内路径，不依赖原电脑的图片文件夹。原文件另存时，可用 `DIRMAP_RECOGNITION_SOURCE=/路径/原图.jpg` 指定测试输入；脚本会核对文件哈希。

仓库公开托管在 [Kibiandkimi/DirMap](https://github.com/Kibiandkimi/DirMap)。推送 `main` 后，GitHub Actions 自动测试、构建并部署到现有服务器，保留服务器教学数据；内部健康检查失败会回滚。配置、依赖更新和恢复方式见 [自动部署说明](deploy/README.md)。

各次最新修改的验证见 [实施状态](IMPLEMENTATION_STATUS.md) 顶部记录；[verification-summary.json](evidence/runtime/verification-summary.json) 保留较早阶段的汇总，可用 `tools/summarize_verification.py` 汇总已保存的验证记录，但不会自动重跑检查。独立配准基准、完整通行语义（尤其可翻越墙、桥隧与楼层连接的自动识别）及真机/校园验收仍未完成。
